§01 About this reference

This is the complete, precise specification of Plainly v0.2. Every rule here is enforced by the real compiler, and every example is runnable.

Plainly is a small, human-first programming language. This reference covers everything the language can do — no more, no less. If a feature isn't on this page, it doesn't exist yet (see §16 Current limitations).

FactValue

§02 Design philosophy

Four rules govern every language decision.

1 · Human-first, not human-onlyprinciple

Syntax reads like English where English is precise: say, set, for each … in. Where English would be vague, the language is mechanical — one way to do each thing. Human-friendly ≠ ambiguous.

2 · Errors are the productprinciple

Every diagnostic has: a stable code (PL-XXX), a plain-English message, a source excerpt with a caret, a hint (often the exact fix), and a did-you-mean suggestion for misspelled names. plainly explain PL-002 expands any code into a short lesson.

3 · Check early, fail informativelyprinciple

The semantic analyzer reports all static problems in one pass — unknown names, wrong argument counts, return outside functions, unused variables (as warnings) — before anything runs.

4 · Small enough to fully knowprinciple

16 keywords + 18 builtins is the entire language. A motivated reader can understand every rule on this page in an afternoon — and then understand what big languages are doing underneath.

§03 Lexical rules

How source text is chopped into tokens.

Source encoding & lines

  • Files are UTF-8 text, extension .pl.
  • Statements are separated by newlines — one statement per line.
  • Blank lines are ignored everywhere; they never affect indentation.

Indentation

  • A block is opened by : at the end of a line and contains lines indented 2 spaces deeper.
  • Indentation must be a multiple of 2. Odd widths (e.g. 3 spaces) are error PL-004.
  • Every line inside one block must align exactly; misalignment is PL-004.
  • Tabs count as advancing to the next multiple of 4 — but spaces are strongly recommended.

Comments

# starts a comment that runs to the end of the line. Comments may be full-line or trailing. There are no block comments. See §13 Comments.

Identifiers

Start with a letter or _, continue with letters, digits or _. Case-sensitive: total ≠ Total. Reserved words cannot be used as names (they're listed per-section below; the lexer would read them as keywords).

Numbers

  • Integers: 0, 42, 9000
  • Decimals: 3.14, 0.5 (a digit required on both sides of the dot)
  • No exponent notation, no hex, no negative literals (use unary -).

Strings

  • Double quotes only: "hello". Single quotes are error PL-005.
  • Escapes: \n newline, \t tab, \" quote, \\ backslash. Unknown escapes are PL-006.
  • A string must close on the same line, or error PL-003.

Operators & punctuation

+ - * / % > < >= <= == =, : , ( ) [ ]. Any other character is PL-001 with a did-you-mean hint.

Reserved words (16)

say set if otherwise for each in repeat times function return true false and or not

§04 Values & types

Plainly has five kinds of values. There is no type annotation syntax — values carry their kind.

KindWritten asExamplesTruthiness (used in if)
Numberdigits, optional decimal42 3.14 -7false when 0
Textdouble-quoted"hi" ""false when empty
Booleankeywordstrue falseas itself
List[v, v, …][1, "a"] []false when empty
Functiondeclared, not written literallydouble, builtinsalways true

There is also exactly one "missing" value: a function that ends without return gives back nothing (printed as nothing).

⚠️

0, "" and [] are false inside if. This rarely matters in practice, but it's specified. Prefer explicit comparisons: if count == 0:.

Converting between kinds

Use number(value) and text(value) — see §14 Standard library. Implicit conversion happens only when joining text with +.

§05 Variables

set creates or updates a named box.

set NAME = EXPRESSIONstatement

Evaluates EXPRESSION, then stores it under NAME. If a visible variable of that name exists, it is updated in place; otherwise a new one is created in the current scope.

Right side is evaluated before assignment, so set score = score + 10 reads the old value first.

set count = 3
set count = count * 10
say count
Output

        

      


      
Scoping rules

      
    
        
  • Top level: variables live for the whole program.
    • 
        
  • if / otherwise / repeat blocks: no new scope — a set inside
        updates the surrounding variable (this is how accumulators work).
    • 
        
  • for each loops: the loop variable is fresh each pass and visible only
        inside the body.
    • 
        
  • Functions: parameters are local. A set of an unknown name
        inside a function creates a local; assigning to a known outer name updates the outer one.
    • 
        
  • Reading a name that was never created is error PL-002 — statically caught
        by the analyzer, with a did-you-mean hint.
    •

§09 if / otherwise

      
Conditional execution with indentation-delimited blocks.


      
if-stmt     := "if" expression ":" block
                 ( "otherwise" ( if-stmt | ":" block ) )?
block        := NEWLINE INDENT statement+ DEDENT


      

        
if COND: … otherwise: …statement

        

          
Evaluates COND; if truthy, runs the if block; else the
          otherwise block. otherwise is optional; chaining via
          otherwise if builds multi-way branches — the first true condition wins and
          the rest are skipped entirely.

          
set score = 85
if score >= 90:
  say "A"
otherwise if score >= 80:
  say "B"
otherwise:
  say "F"

          
Output

        

      


      
    
        
  • The colon after the condition is mandatory (PL-005 otherwise, with a hint).
    • 
        
  • An empty block is PL-007 — put at least one line inside.
    • 
        
  • Blocks do not create scope; set inside updates outer variables.
    • 
        
  • Conditions may be any value; see truthiness in §04.
    • 
      

    


    
    

      
§10 Loops

      
Two loop forms cover every repetition need.


      

        
for each NAME in ITERABLE: …statement

        

          
Iterates a list (each item) or text (each single
          character). Anything else is a runtime PL-009.

          
for each c in "ab":
  say c
for each x in [10, 20]:
  say x

          
Output

          
The loop variable is declared fresh for every pass and visible only
          inside the body. Looping over a huge list copies nothing — iteration is by reference.

        

      


      

        
repeat COUNT times: …statement

        

          
Runs the block COUNT times. COUNT must be a whole number ≥ 0
          (runtime PL-009 otherwise). repeat 0 times: legitimately does
          nothing.

          
repeat 3 times:
  say "hi"

          
Output

          
There is no while loop in v0.2 — see
          §16. Use repeat with a known count, or
          for each over a list.

        

      

    


    
    

      
§11 Lists

      
Ordered collections of any values.


      
Creating & reading

      
set xs = [10, 20, 30]
say xs[0]
say xs[2]
say xs[1 + 1]

      


      
    
        
  • Positions start at 0; the last valid position is length(xs) - 1.
    • 
        
  • Out-of-range reads are runtime error PL-012 with a helpful message.
    • 
        
  • Lists may hold any mix of values, including other lists:
        [[1, 2], [3, 4]] is a grid; grid[1][0] is 3.
    • 
        
  • Text may be indexed the same way: "abc"[1] is "b".
    • 
      


      
Growing & combining

      
    
        
  • push(xs, v) — adds v to the end of xs in place.
    • 
        
  • xs + ys — a new list with all items of both; neither changes.
    • 
        
  • list(a, b, …) — builds a fresh list from any values.
    • 
      


      
Comparing & searching

      
    
        
  • xs == ys — true when same length and each pair is ==.
    • 
        
  • contains(xs, v) — true when any item equals v.
    • 
        
  • length(xs) — item count.
    • 
      

    


    
    

      
§12 Functions

      
Named, reusable recipes with inputs and an output.


      
function-decl := "function" IDENT "(" (IDENT ("," IDENT)*)? ")" ":" block
return-stmt  := "return" expression?


      

        
function NAME(P1, P2): … return …statement

        

          
Declares a function. Calling it with the wrong number of arguments is
          PL-011 — checked statically by the analyzer for known functions.
          Duplicate parameter names are PL-014.

          
function add(a, b):
  return a + b
say add(2, 3)

          
Output

        

      


      
Return semantics

      
    
        
  • return ends the call immediately, handing back one value.
    • 
        
  • return with no value, or falling off the end of the body, returns
        nothing.
    • 
        
  • return outside any function is caught statically: PL-013.
    • 
      


      
Closures & recursion

      
    
        
  • Functions remember the scope where they were defined (a closure), so they can
        read variables from around their declaration.
    • 
        
  • Recursion works: a function may call itself; make sure a base case exists (see The
        Book, chapter 11).
    • 
        
  • Functions are values: you can set f = add and then call f(1, 2).
    • 
      

    


    
    

      
§13 Comments

      
Notes for humans; completely ignored by the compiler.


      
# Full-line comment
set x = 5  # trailing comment
# say "this line does nothing"

      


      
    
        
  • # anywhere on a line starts the comment, which runs to the newline.
    • 
        
  • Comments are stripped by the lexer — they never affect indentation or parsing.
    • 
        
  • No block comments; repeat # per line.
    •

§15 Error codes PL-001 … PL-017

      
Every diagnostic in the language: what triggers it, whether it stops the program, and the fix.


      
Diagnostics come in two severities: errors (stop the program; a
      plainly check failure) and warnings (printed, program still
      runs). Format:


      
PL-002 at line 2, column 5: You tried to use 'agge', but it doesn't exist yet.

    say agge
        ^^^^
Hint: Did you mean 'age'?


      

        
CodeSeverityTriggered whenThe fix

        
PL-001errorA character outside the language appears in codeRemove it; check for typos (lexer suggests)

        
PL-002errorA name is used that was never created (analyzer + runtime)Fix spelling (did-you-mean) or set it first

        
PL-003errorA string has no closing "Close the quote on the same line

        
PL-004errorIndentation is odd or misaligned2 spaces per level; align block lines

        
PL-005errorGrammar violated (missing colon, stray token…)Message names what was expected; hints for : ) ]

        
PL-006errorUnknown \ escape in a stringUse \n \t \" \\

        
PL-007errorBlock after : has no statementsAdd an indented line

        
PL-008error/ or % with zero divisorCheck the divider before dividing

        
PL-009errorA value of the wrong kind reaches an operation or builtinConvert with number()/text(); see operator table §07

        
PL-010errorCalling a value that isn't a functionCheck the name

        
PL-011errorWrong argument count (builtins checked statically too)Match the signature; plainly explain <fn>

        
PL-012errorIndex outside 0 … length-1Guard with if i < length(xs):

        
PL-013errorreturn appears outside a functionMove it inside (caught statically)

        
PL-014errorA function declares the same parameter twiceRename (caught statically)

        
PL-015warningA variable (or loop variable) is set but never usedUse it or remove it — the program still runs

        
PL-016errorOperation unsupported for these kinds (e.g. [1] - [1])Numbers subtract, text joins, lists combine

        
PL-017errorReserved word used as a variable/function namePick another name

      


      

        🧭
        
From the terminal: plainly explain PL-011 prints a short lesson on any code;
        plainly explain split documents any builtin.

      

    


    
    

      
§16 Formal grammar (EBNF)

      
The whole language, formally. This is what the parser implements.


      
program       := statement*

statement     := say-stmt | set-stmt | if-stmt | for-each-stmt
               | repeat-stmt | function-decl | return-stmt | expr-stmt

say-stmt      := "say" expression
set-stmt      := "set" IDENT "=" expression
if-stmt       := "if" expression ":" block
                 ( "otherwise" ( if-stmt | ":" block ) )?
for-each-stmt := "for" "each" IDENT "in" expression ":" block
repeat-stmt   := "repeat" expression "times" ":" block
function-decl := "function" IDENT "(" params? ")" ":" block
params        := IDENT ( "," IDENT )*
return-stmt   := "return" expression?
expr-stmt     := expression
block         := INDENT statement+ DEDENT

expression    := or-expr
or-expr       := and-expr ( "or" and-expr )*
and-expr      := eq-expr ( "and" eq-expr )*
eq-expr       := cmp-expr ( ( "==" | "!=" ) cmp-expr )*
cmp-expr      := add-expr ( ( ">" | "<" | ">=" | "<=" ) add-expr )*
add-expr      := mul-expr ( ( "+" | "-" ) mul-expr )*
mul-expr      := unary-expr ( ( "*" | "/" | "%" ) unary-expr )*
unary-expr    := ( "not" | "-" ) unary-expr | postfix-expr
postfix-expr  := primary ( call-suffix | index-suffix )*
call-suffix   := "(" args? ")"
index-suffix  := "[" expression "]"
args          := expression ( "," expression )*
primary       := NUMBER | STRING | "true" | "false" | IDENT
               | "[" args? "]" | "(" expression ")"


      
Tokens INDENT/DEDENT/NEWLINE are synthesized by the
      lexer from indentation — the same design Python uses. A tree-sitter grammar mirroring these
      rules lives in grammar/tree-sitter-plainly/ for editor tooling.

§18 How the compiler works

      
Five stations between your text and its behavior.


      
source.pl
  ↓ tokenize()      src/lexer.ts      → Token[]       (words, strings, INDENT/DEDENT, positions)
  ↓ parse()         src/parser.ts     → Program (AST) (precedence climbing, block rules)
  ↓ analyze()       src/analyzer.ts   → Diagnostic[]  (all static checks in one pass)
  ↓ Interpreter     src/interpreter.ts→ output        (tree-walking executor + Environment chain)
  ↓ formatValue()   src/format.ts     → display text  (shared by say, text(), join())


      
Design notes worth knowing

      
    
        
  • Positions everywhere. Every AST node carries line/column; every
        diagnostic uses them for the caret.
    • 
        
  • Suggestions are distance-based. Misspelled names are compared to all
        visible names + builtins with capped Levenshtein distance; only close matches are offered.
    • 
        
  • The analyzer models scopes exactly like the interpreter — if check
        passes, the names will resolve the same way at runtime.
    • 
        
  • Builtins are ordinary values (native functions) living in the global
        environment; shadowing them is allowed but warned about.
    • 
        
  • Short-circuit evaluation: and/or never
        evaluate the right side unless needed.
    • 
      


      
Public API (for embedding)

      
import { runSource, checkSource, compileToAst, analyze,
       formatError, ERROR_CODES, STDLIB_DOCS } from "plainly"

runSource(src, print)      → { output, warnings }   (throws PlainError)
checkSource(src)           → { ok, diagnostics, ast }
compileToAst(src)          → Program                 (throws on syntax errors)
